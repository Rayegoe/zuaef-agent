# X/Twitter 线程写作指南

公众号文章是坐着读的。X 线程是站着读的。

好的线程，不是把文章切成 8 段。是从同一个故事里，抽出另一条更短的线来重新讲。每条 tweet 像一粒珠子——独立、完整、有自己的光泽。串起来之后，是一根线，不是一堆散珠。

> 如果把公众号文章比作一次炉边谈话，X 线程就是派对上抓住你胳膊说的那两分钟。

---

## 不是步骤，是节奏

没有"先写 Hook，再写 Body，再写 CTA"这种顺序。线程是跟着一种节奏感走的：

- **第一条**：制造一个缺口。"后面有东西。"读者看到最后一行的时候，应该想往下翻。
- **中间 3-8 条**：每条讲清楚一件事。不多，不少。
- **最后一条**：不是号召，是停顿。一个安静的判断，或者一句让读者留在那里想一会儿的话。

---

## 每条 tweet 的质地

### 长短交替

一条长 tweet（3-4 行）之后，跟一条短的（1-2 行）。长的展开想法，短的制造节奏上的停顿。一整屏都是长 tweet 让人读着累，一整屏都是短 tweet 让人觉得琐碎。

### 独立阅读

每条 tweet 应该能在时间线上独立被理解。不依赖前一条。读者的时间线是被打碎的——他可能只看到第三条，然后走了。第三条应该自己说得过去。

### 递进，不等于并列

每一条应该比前一条多走一步。不是"第一…第二…第三"的并列，是"这件事还不止这样——其实更关键的是——而很少有人注意到的是——"。

---

## 关于第一条（Hook）

第一条的任务不是"概括全文"。是制造一个缺口。

四类缺口：

**反直觉**：
> 大多数中小企业现在不需要 AI Agent。他们需要的是先把资料整理干净。

**从自己的困惑开始**：
> 过去半年我们试了 17 个 AI Agent 方案。90% 的失败原因不是 AI 不够好，是我们自己的企业环境它还不认识。

**从一个具体场景出发**：
> 想象一下：你的客户资料在销售微信里，产品报价在三个不同的 Excel 里，交接靠口头。这时候塞一个 AI 进去——它活不了。

**直接摆出判断**：
> AI Agent 现在不是玩具，也不是救命稻草。它是一个需要特定土壤才能活的东西。

不需要在第一条里解释。只需要让人想读第二条。

---

## 中间条：每条讲透一件事

每条 tweet 讲一个点。不多讲。

结构可以这样感觉：

```
{一个判断，或一个观察}

展开一两句——为什么这个判断是对的

一个具体的例子，或你亲眼见过的事

→ 一句落脚的话（不是总结，是让这句话停住）
```

**不要做的**：
- 不用"第一""第二""第三"（tweet 自身的编号 2/N 已经承担了序列任务）
- 不用"让我们深入探讨""值得注意的是"——X 上没人这样说话
- 不用 emoji 密集轰炸。一条 tweet 不要超过 1 个 emoji
- 不用 markdown 标题语法

**要做的**：
- 每条 tweet 自带一个立足点。读完了，至少带走一个想法
- 宁少勿多。一条 tweet 装不下三个论点
- 如果某条 tweet 用一屏写不完，说明你需要砍，不是加

---

## 最后一条：让线停下来

收尾不写"关注我获取更多"。不写"如果觉得有用请转发"。

三联的结尾不是运营动作。收尾是一个停顿——让读者在翻完这条线之后，停在那里想一会儿。

```
{一句安静的判断}

——比大声喊出来的号召更有力。
```

比如：

> 所以真正的问题是：你准备好让 AI 进入你的工作现场了吗？不是技术问题。是环境问题。

或者：

> 中小企业现在最该做的，不是追赶 AI，是先把企业建设成一个 AI 能干活的现场。

如果需要一个标签，1-2 个就够了。不要超过 3 个。

---

## 长度与节奏

- 最少 5 条，最长 12 条。超过 12 条通常意味着砍得还不够。
- 5-7 条：观点集中的文章
- 8-10 条：方法或观察型的文章
- 11-12 条：需要多层次展开的分析

长度节奏大致是这样的：

```
长（展开一个想法）→ 短（一句话落地）
长（进一步展开）→ 短（一个具体例子）
长（为什么这很重要）→ 短（一个反问或过渡）
...
```

---

## 关于配图

线程中最多 2 条 tweet 可以带图。带图不是为了好看，是为了帮读者"看到"你正在说的东西。

如果图片不能帮助理解，比不带图更差。

---

## 最后

写完之后，从头到尾读一遍。拿掉所有你觉得"这段有点水"的句子。最后留下来的东西，如果有人只看到其中一条，也应该觉得这条 tweet 本身值得读。
